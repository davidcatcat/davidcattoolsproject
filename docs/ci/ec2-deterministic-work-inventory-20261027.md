# EC2 deterministic development work inventory

> **2026-11-09 note:** llmtool Linux CI no longer runs on EC2; it runs on GitHub-hosted `ubuntu-24.04` ([#1253](https://github.com/davidcatcat/davidcattoolsproject/issues/1253), [#1256](https://github.com/davidcatcat/davidcattoolsproject/issues/1256)). EC2 remains for `llmtool task remote-test`, a PM pre-review tool on private infrastructure, not CI. The inventory below is historical.

Scope: identify repeated development-time work that can be run or summarized deterministically, using existing llmtool code and the approved EC2 Linux execution route. This is an inventory, not evidence that a remote job ran. The available sources document no measured model-call or token savings; those remain **UNKNOWN** until matched work and usage are measured.

The current Linux workflow checks out the requested immutable PR-head/commit SHA only after its admission and runner-boundary checks, then runs `make -C tools/llmtool check` on Python 3.14. Python 3.9 is a manually started pre-release matrix option. The Mac workflow keeps the macOS 3.13 and native gates on Mac. Skipped jobs are not passes. See [.github/workflows/llmtool-linux-ci.yml](../../.github/workflows/llmtool-linux-ci.yml) and [.github/workflows/llmtool-mac-ci.yml](../../.github/workflows/llmtool-mac-ci.yml).

The roadmap authorizes a bounded immutable-SHA EC2 PoC and calls for compact, source-bound receipts back to the same task. Ordinary checkout cannot test an uncommitted Mac worktree; a separate provenance-checked transfer would need authorization. The roadmap says no real job or token saving is verified yet. Existing EC2 runners are non-admin, isolated by account, use job-owned virtual environments, and are admitted by workflow/actor/repository checks; their number is Owner-reported, not independently attested in this document. See [tools/llmtool/ROADMAP.md](../../tools/llmtool/ROADMAP.md) and [tools/ec2-runner/README.md](../../tools/ec2-runner/README.md).

## Ranked implementation candidates

Ranked for low risk and repeated mechanical work, subject to source-bound receipts and the existing acceptance gates:

1. **Parse and return bounded test receipts**: reuse TEST-3 counts/digests and failure excerpts; add/complete the connection to the same task. This removes routine log copying while preserving model diagnosis. The roadmap describes remote receipt integration as planned, not verified.
2. **Run admitted immutable-SHA Linux checks and return compact evidence**: reuse existing Linux workflow admission, exact-HEAD check, job venv and canonical `make check`. Receipt must carry run/job identity, SHA, exit status, counts, digest, and explicit error/NOT_RUN states. No new runner or generic remote abstraction.
3. **Automate deterministic source evidence collection**: reuse Git snapshot and review manifest/bundle logic for HEAD, status, changed paths, diff and SHA256; add only missing deterministic fields such as diff statistics after confirming requirements. Keep dirty/uncommitted data local unless separately authorized.
4. **Reuse TEST-1/3 selection for local iteration**: execute only mapped low-risk tests and report L0/L1/L2/L3 plan and fallback reason; retain full CI, security, exact-head, and native gates. Selector is not currently pipeline-integrated.
5. **Implement ENV-2 cache preflight using ENV-1 rules**: reduce repeated setup/download work without sharing writable environments. Validate fingerprints/digests and task isolation before claiming a warm-cache benefit.

The ranking is a prioritization judgment, not measured repetition or savings. Test execution consumes compute; a reduction in model calls/context must be measured from matched tasks and actual provider usage telemetry. Where telemetry or runtime evidence is absent, report **UNKNOWN**.
