# NLF Fix Round 1 Report

日期：2026-09-28
範圍：`tools/nlf`（v0.1.0 → 建議標為 v0.1.1）
狀態：已修正、未 commit、未 push、未 release

## Summary

這一輪修的是 code review 中確認會「誤判、默默擴大搜尋範圍、錯誤結果」的問題，原則是**看不懂就報錯，不要默默猜錯**：

- 未加引號的路徑含中文時不再被截斷（以前 `在 ~/文件` 會變成搜尋整個 `~`）。
- `without` / `不包括` 改為否定條件並報錯，不再被當成「排除目錄」；`except` / `除了` / `不要` 必須接「目錄／以外／dir」才算排除。
- 排除清單不再吃掉後面的副檔名條件（`exclude vendor and go files`）；`排除 .go`、`exclude *.log`、`exclude go files` 這類檔案類型的排除改為報錯。
- 排除路徑會正規化（`./src/gen`、`src/gen/`、root 底下的絕對路徑、`~/…`），root 之外的路徑報錯；大小寫依檔案系統實際解析結果判斷，不再假設 case-insensitive。
- `""` 空字串內容報錯。
- 未加引號的中文內容延伸到空白／標點為止；與關鍵字黏在一起而範圍不明時報錯要求加引號，不再默默截短。
- 數量、時間、大小的溢位改為明確的 parse error。
- 支援任意英數字副檔名 + 檔案名詞（`找 ovpn 檔`、`find pem files`、`找 tfstate 檔`）。
- `--explain` 改稱「近似」指令，並修正 symlink root、只 prune 目錄、相對排除路徑、root 以 `-` 開頭。

production search 仍是原生 Go 走訪，不執行任何 shell；沒有新增寫入、刪除、sudo 或提權。

## Issues Fixed

### 1. Parser path truncation

- **原問題**：`在 ~/文件` 的 root 變成 `~/`，「文件」被當 filler 忽略；`在 ~/圖片` 變成「整個 home + 圖片副檔名」。
- **原因**：tokenizer 的 ASCII 詞遇到第一個非 ASCII 字元就結束，路徑被切成 `~/` + 中文 token。
- **修法**：以 `/`、`~/`、`./`、`../` 開頭的詞會一路吃到空白、分隔標點或引號為止，包含非 ASCII（`tokenize.go` `hasPathPrefix` / `isPathRune`）。路徑後面直接黏著文字時（`在 ~/文件裡找`）會變成不存在的路徑而明確失敗（exit 2），並提示加空白或引號，不會退回較大的 root。
- **Behavior before**：`HOME=<sandbox> nlf '在 ~/文件'` 列出 `other/secret.txt` 等整個 home 的檔案，exit 0。
- **Behavior after**：只列出 `文件/doc.go`；`在 ~/文件裡找 go 檔` → `找不到搜尋位置「…/文件裡找」` + 提示，exit 2。
- **Regression test**：`TestParse`（`在 ~/文件 找 go 檔`、`in ~/Documents/報告 pdf files`、`在 ./中文路徑 找 txt 檔`、`在 ~/圖片`、帶空白的引號路徑）、`TestChinesePathIsNeverCutShort`、`TestPathWithSpaces`。

### 2. Negative/exclude ambiguity

- **原問題**：`files without TODO`、`不包括 TODO 的檔案` 被解析成「排除名為 TODO 的目錄」，回傳全部檔案，exit 0。
- **原因**：`without`、`不包括` 在 `excludePhrases` 裡。
- **修法**：`without`、`不包括` 移到 `notPhrases`（v0.1 否定條件報錯）。`except`、`except for`、`除了`、`不要` 改為弱排除詞：名稱後面必須有「目錄／資料夾／以外／之外／dir／folder」等字才算排除，否則報「無法確定是要排除目錄還是否定條件」。`exclude`、`excluding`、`排除`、`skip`、`跳過`、`ignore`、`忽略`、`not in`、`outside of`、`不含目錄` 維持直接排除。
- **Behavior before**：`files without TODO` → ExcludeDirs=[TODO]，列出所有檔案。
- **Behavior after**：`negative conditions are not supported in v0.1: "without"`，exit 2；`except vendor` 報錯並提示 `exclude vendor`；`except vendor dir`、`除了 build 以外`、`不要 tmp 目錄` 正常排除。
- **Regression test**：`TestParseErrors`（`files without TODO`、`不包括 TODO 的檔案`、`不含 TODO`、`except vendor`、`不要 tmp`、`除了 TODO`）、`TestParse`（`except vendor dir`、`不要 tmp 目錄`，以及既有的 `除了 build 以外`）。

### 3. Exclude swallowing extension

- **原問題**：`exclude vendor and go files` → ExcludeDirs=[vendor, go]，而且沒有副檔名條件；`排除 .go`、`排除 *.log` 被當目錄名，對檔案毫無作用。
- **原因**：`excludeNames` 在分隔詞之後接受任何 `tWord`／`tExt`，沒檢查後面是不是「副檔名 + 檔案名詞」。
- **修法**：
  - 分隔詞（and／和／、…）或空白之後，如果接的是「副檔名清單 + 檔案名詞」（`extNounAhead`），排除清單在此結束，交給副檔名解析。
  - 排除名稱後面直接接檔案名詞（`exclude go files`、`exclude test files`）→ 報「v0.1 只能排除目錄」。
  - 看起來是檔案類型的名稱（glob `*.log`、已知副檔名 `.go`、別名 `images`）→ 報錯，除非加「目錄」／`dir` 或引號（`排除 ".go"`）。`.git`、`.venv` 等非副檔名的點開頭目錄照常可用。
- **Behavior before**：見原問題。
- **Behavior after**：`exclude vendor and go files`、`排除 vendor 和 go 檔` → ExcludeDirs=[vendor]、Extensions=[go]；實跑只列出 `m.go`、`src/gen/s.go`。`排除 .go` → 「這看起來是檔案類型；v0.1 只能排除目錄」，exit 2。
- **Regression test**：`TestParse`（`exclude vendor and go files`、`排除 vendor 和 go 檔`、`exclude vendor and go and md files`、`exclude vendor and ovpn files`、`排除 ".go"`、`exclude logs dir`）、`TestParseErrors`（`exclude go files`、`exclude test files`、`除了 go 檔以外`、`排除 .go`、`exclude *.log`、`exclude images`）、`TestExcludeWithExtensionEndToEnd`。

### 4. Exclude path normalization

- **原問題**：`排除 SRC/gen`（大小寫不同）、`exclude <root 底下的絕對路徑>`、`排除 ~/proj/vendor` 都默默失效；explain 對 `./src/gen` 產生 `-path ././src/gen`。
- **原因**：`excluded()` 只做 `filepath.Clean(d) == rel` 的精確比對；沒有處理 `~` 和絕對路徑；名稱比對則寫死 `EqualFold`（註解假設 macOS 一定 case-insensitive）。
- **修法**：
  - `search.NormalizeExcludes(root, dirs)`：含 `/` 的排除一律轉成相對 root 的 `./rel` 形式（clean、去掉結尾 `/`）；絕對路徑轉成相對 root，並在必要時用 `EvalSymlinks` 比對（`/tmp` vs `/private/tmp`）；在 root 之外，或就是 root 本身，回傳 `*ExcludeError`，main 以雙語報錯並 exit 2。`main.go` 在正規化前先做 `~` 展開，`--explain` 與搜尋使用同一份正規化結果。
  - 大小寫：路徑的精確比對永遠成立；大小寫不同的寫法，只有當 `os.Lstat(root/寫法)` 與實際走訪到的目錄是 `os.SameFile` 時才排除。所以 case-insensitive 檔案系統（macOS APFS 預設）會排除，case-sensitive 檔案系統不會，不再假設平台行為。
  - 名稱排除（不含 `/`）維持 README 文件寫明的「不分大小寫」。這在 case-sensitive 檔案系統上只會多排除、不會擴大搜尋範圍，這輪不改。
- **Behavior before**：`go files exclude SRC/gen` 仍列出 `src/gen/s.go`。
- **Behavior after**：`./src/gen`、`SRC/gen`（APFS 上）、root 底下的絕對路徑、`~/proj/vendor` 都能排除；`exclude ../x` → `exclude path is outside the search location`，exit 2。
- **Regression test**：`TestNormalizeExcludes`、`TestExcludeRelativeAndAbsolutePaths`、`TestExcludePathCaseFollowsFileSystem`（依執行時的檔案系統判斷期望值）、`TestExcludePathErrors`（含 `~` 排除）。

### 5. Empty content

- **原問題**：單獨的 `""` 變成空字串內容條件，所有文字檔都符合。
- **原因**：`step()` 處理 bare quoted 的分支沒做 `contentTerm()` 裡的空字串檢查。
- **修法**：兩處共用 `errEmptyContent()`，bare quoted 空字串也報錯。
- **Behavior before**：`nlf '""'` 列出全部 8 個檔案。
- **Behavior after**：`""`、`包含 ""`、`containing ""`、`go files ""` → `search text must not be empty` / 「要搜尋的內容不能是空字串」，exit 2。
- **Regression test**：`TestParseErrors`（上述四種）。

### 6. Chinese content truncation

- **原問題**：`包含 設定檔` 實際搜 `"設定"`（範圍變寬）；`包含 10個` 實際搜 `"10"`；`包含 系統 錯誤` 被合併成 `"系統錯誤"`（空白消失）。
- **原因**：`contentTerm` 只取一個 token，tokenizer 又會把「檔」「個」等關鍵字切出去；未知中文會跨空白合併。
- **修法**：
  - 未加引號的內容由連續、沒有空白分隔的 token 組成（例如 `API` + `連線失敗` → `API連線失敗`）。
  - 如果緊接著的是 nlf 認得的關鍵字，只有連接詞（`的`、`且`、`和`、`或`…，`contentBoundaries`）可以當邊界；其他關鍵字 → 報「要搜尋的文字與關鍵字連在一起，無法確定範圍」，並給兩種加引號的寫法。
  - tokenizer 不再跨空白合併未知中文。
- **Behavior before**：見原問題。
- **Behavior after**：`包含 錯誤訊息`、`內容包含 系統錯誤`、`找內容有 API連線失敗 的檔案` 完整解析；`包含 設定檔`、`包含 10個`、`包含 系統有問題` 報錯並要求加引號；`包含 系統 錯誤` → 「看不懂這個詞：錯誤」。既有的 `包含TODO且大於1MB` 維持可用。
- **Regression test**：`TestParse`（`包含 錯誤訊息`、`內容包含 系統錯誤`、`找內容有 API連線失敗 的檔案`、`包含 錯誤訊息，大於 1KB`）、`TestParseErrors`（`包含 設定檔`、`包含 10個`、`包含 系統有問題`、`包含 系統 錯誤`）。

### 7. Numeric overflow

- **原問題**：`top 99999999999999999999` 在 int 轉換時溢位成負數，數量上限消失；`last 1000 years` 在 Duration 溢位後變成 1734 年；大小檢查用 `>` 比較 `float64(MaxInt64)`（其實是 2^63），`8388608 TB` 正好等於 2^63，轉型溢位。
- **修法**：數量 > `math.MaxInt32` 報「數量太大」；時間長度 ≥ 2^63 ns（約 292 年）報「時間範圍太大」；大小 ≥ 2^63 bytes 報「檔案大小太大」（`maxInt64Float` 常數）。超大數字字串解析成 +Inf 時同樣會被擋下。
- **Behavior before**：上限默默失效或時間界限錯誤，exit 0。
- **Behavior after**：明確 parse error，exit 2；邊界值 `top 2147483647`、`last 292 years` 仍可用。
- **Regression test**：`TestParseErrors`（`top 99999999999999999999`、`top 2147483648`、`last 1000 years`、`last 99999999999999999999 days`、`larger than 8388608 TB`、`larger than 99999999999999999999 GB`）、`TestParse`（`top 2147483647`、`last 292 years`）。

### 8. Arbitrary extension support

- **原問題**：`找 ovpn 檔`、`find ovpn files` 因為 `ovpn` 不在 `extAliases` 而報「看不懂」。
- **修法**：`extension()` 先嘗試「任意英數字詞（≤10 字元）＋檔案名詞」；沒有名詞也沒有 trigger（`副檔名`／`extension`）時，退回原本只認得別名與 `.ext` 的規則。為避免把一般英文詞當副檔名：
  - 已有意義的關鍵字（`reserved`）不算，除非前面有明確的 trigger。
  - 常見形容詞／動詞（`large`、`old`、`new`、`hidden`、`test`、`config`、`delete`、`remove`… 共約 60 個，`notExtWords`）不算，會變成「看不懂」錯誤。
  - `extAliases` 保留作分類別名（`python`→py、`images`→jpg/png/…、`word`→doc/docx）。
- **Behavior before**：`找 ovpn 檔` → 看不懂「ovpn」，exit 2。
- **Behavior after**：`找 ovpn 檔` 列出 `a.ovpn`、`conf/b.OVPN`；`find pem files`、`找 tfstate 檔`、`找 conf 檔案` 都可用；`find ovpn`（沒有名詞）、`large files`、`delete files` 仍報錯。
- **已知取捨**：任何不在 `notExtWords` 裡的英數字詞加上 `files` 都會被當成副檔名，例如 `find banana files` 會變成 `*.banana`。結果是「縮小範圍，0 筆、exit 1」，不會擴大範圍，`--explain` 也會顯示。因此既有測試 `find banana files`（原本期望「看不懂 banana」）改用 `find files banana` 保留原意（未知詞 → exit 2），並新增一筆測試明確記錄 `find banana files` = `*.banana`。
- **Regression test**：`TestParse`（`找 ovpn 檔`、`find ovpn files`、`find pem files`、`找 tfstate 檔`、`找 conf 檔案`、`ovpn 和 pem 檔`、`find banana files`、`.ovpn`、`副檔名是 ovpn`，以及別名不退化：`find python files`、`word 檔`、`images`、`go files larger than 1kb`，另外既有的 `c files`、`找圖片`、`go 或 md 檔` 都保留）、`TestParseErrors`（`large files`、`delete files`、`find ovpn`）。

### 9. --explain partial fixes

- **原問題**：README 與 help 宣稱「等效」；實測 `--dir <symlink>` / `/tmp` 時 find 找到 0 筆；`-iname vendor -prune` 也會把名為 vendor 的**檔案** prune 掉；`-path ././src/gen` 對不到；root 以 `-` 開頭時產生 `find -rt`。
- **修法**：
  - 文案：中文「近似的 macOS 指令（僅供參考，nlf 不會執行它）」；英文「Approximate macOS command for reference; nlf does not execute it」；help 與 README 同步，README 也列出已知差異。
  - root 是指向目錄的 symlink 時（由 main 設定 `Query.RootSymlink`），find root 補 `/`（BSD find 輸出 `lnk/x`，與 `-path` 一致，已實測）。
  - prune 改為 `-type d \( … \) -prune`。
  - 排除路徑經 `path.Clean` 並以 `root/rel` 組合。
  - root 以 `-` 開頭時補 `./`。
  - shell quoting 沿用原本的 `shellQuote`（單引號跳脫），另外補了含單引號、空白的測試。
- **Behavior before**：`--dir /tmp 'files'`：nlf 15663 筆、explain 指令 0 筆。
- **Behavior after**：同一查詢兩邊都是 15795 筆；symlink root + `exclude vendor` 兩邊都只有 `lnk/a.txt`；`--dir -rt` → `find ./-rt …`。
- **Regression test**：`TestFindCommand`（symlink root、`-` 開頭 root、只 prune 目錄、相對／未正規化排除路徑、symlink root 下的排除路徑、quoting）、`TestExplainSaysApproximate`、`TestExplainSymlinkRootAndRelativeExclude`、`TestExplainParity`（macOS 上實際執行產生的 find 指令，與 nlf 結果做集合比較：`txt files`、`exclude vendor`、`exclude ./src/gen`、`exclude src/gen/`、`larger than 1KB`、`at most 1KB`、`containing "TODO"`、`largest 1`）。

## Remaining Known Issues

### 建議修（這輪沒修）

- **排序的 top-N 用 O(n) 記憶體**：20 萬個檔案的 `largest 5` 約用 86 MB RSS（沒排序時約 3 MB）。建議改用大小 N 的 heap（依指示這輪不做）。
- **ignore-case 用 `bytes.ToLower`，不是真正的 Unicode case folding**：Kelvin 符號（K，lower 後長度改變）剛好跨 64 KB chunk 時會漏抓；希臘文結尾的 Σ／ς 不相等。
- **binary 偵測只看第一個 64 KB**：NUL 出現在之後的檔案會被當成文字（README 已改為如實描述）。
- **權限提示**：EACCES 與 EPERM（TCC）使用同一段 Full Disk Access 提示；建議的 `--dir ~/Documents` 本身就受 TCC 保護；`Operation not permitted` 被顯示成 "permission denied"。
- **`Report.PermissionDenied` / `OtherErrors` 沒有上限**（只印前 5 筆）。
- **size 條件互相矛盾時不報錯**（`larger than 10MB smaller than 1MB` → exit 1）；time 條件矛盾時會報錯，行為不一致。
- **錯誤訊息有時指錯 token**：`extension webmanifest` 報「看不懂 extension」；`副檔名 tar.gz` 報「看不懂 副檔名」；副檔名有 10 字元上限。
- **輸出不適合接 pipe**：沒有 `-0`／`--null`；檔名含換行會被拆行；相對路徑可能以 `-` 開頭。README 推薦的 `| xargs open` 遇到有空白的檔名會拆錯。
- **中文排除名稱**：沒加空白時仍會被字典切開（例如 `排除 舊資料夾` 會排除「舊」）；和這輪修掉的內容截斷是同一類問題，但範圍較小。
- **`--explain` 仍是近似**：未排序時的順序、同分時的排序、隱藏檔 `.go`（`matchExt` 要求名稱長度大於副檔名）、binary 與大小寫比對都可能不同（README 已列出）。

## Risk Assessment

- **Parser 更嚴格了**：以前能「猜中」的部分寫法現在會報錯，例如 `except vendor`、`exclude logs`（logs 是副檔名別名，需要寫 `exclude logs dir`）、`在 ~/Documents裡找`（路徑黏著中文）、`包含 設定檔`。這是依照「寧可 reject」的原則所做的取捨；每個錯誤都有提示正確寫法，但日常使用會多碰到一些錯誤訊息。
- **任意副檔名規則**：不在 `notExtWords` 裡的英文詞加上 `files` 會被當成副檔名（`banana files`）。只會縮小範圍（0 筆、exit 1），不會擴大；可以用 `--explain` 確認。
- **`notExtWords` 和 `contentBoundaries` 是手工維護的清單**：漏掉的詞只會造成報錯或縮小範圍，不會擴大搜尋範圍。
- **排除路徑的大小寫判斷**依賴 `os.Lstat` 加 `os.SameFile`：如果排除路徑在搜尋途中被建立或刪除，行為以開始搜尋時的狀態為準。
- **production code 的安全面沒有改變**：沒有新增 `os/exec`、寫入、temp 檔、提權；只有測試（`TestExplainParity`）會執行唯讀的 `find`。

## Release Recommendation

以下只是技術建議，是否 release 由你決定：

- **local daily use**：適合。這輪已修掉會默默擴大範圍或搜錯的主要路徑；還有疑慮時可以先用 `--explain` 確認解讀。
- **v0.1.1**：技術上適合標為 v0.1.1。所有必修項目都有對應的 regression test，而且已確認這些測試在修正前的程式上會失敗；fmt、vet、test、race、count=10、build 都通過。目前 `main.go` 的 `version` 常數仍是 `0.1.0`，這輪沒有改，要在 release 時一併決定。
- **stable release**：建議再等一輪。至少要處理 heap top-N（大樹 + largest/newest 的記憶體）、權限提示區分 EACCES/EPERM、`-0` 輸出，並完成 TCC 與 iCloud 的人工驗證，之後再考慮標為穩定版。
