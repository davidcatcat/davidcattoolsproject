## 3. Mandatory C1 — private inherited caller→Host channel

Use **one anonymous, inherited, unidirectional pipe** from the reviewed internal launch owner to `llmtool._git_add_host`, with `Popen(..., shell=False, close_fds=True, pass_fds=(only_caller_to_host_read_fd,))`. The trusted launcher owns write-only end; the Host inherits read-only end and proves it is an open pipe, not an arbitrary file/socket, before any supervisor spawn. Any additional Host→supervisor control/status/liveness pipes remain independently scoped as in B5; do not conflate these two channel layers.

- **No secrets or authority in argv, environment, filesystem path, URL or public CLI flags.** Fixed reviewed child module and isolated `-I` runtime; parent must transfer the FD using a trusted internal bootstrap mechanism with origin/manifest control, not accept an attacker-chosen `--fd` argument.
- Frame format **fixed and bounded**: e.g. 4-byte unsigned big-endian length followed by canonical serialized UTF-8 JSON, hard maximum **16 KiB** for the Host launch handshake (reassess only if the complete canonical typed Action cannot fit; larger scope requires reviewer change), one frame only, strict schema, deadline <=2s before any supervisor launch. Strict EOF/short frame/extra data/invalid UTF-8/oversize/invalid field handling: `NOT_SUPPORTED` or `AUTHORITY_REJECTED`; no child, no sensitive echo.
- Bind protocol/version/domain `A11b.2.2.2/git-add/internal/v1`, fresh strong nonce, intended trusted parent PID plus independently verified kernel identity/start time where supported, exact installed module/artifact manifest digest (reviewed product files, **no fixture or `../tests` paths**), interpreter/install origin, canonical Action digest, `GitAddPreflight` digest, repo dev/inode/root, HEAD/ref/OID, baseline index and expected semantic state, paths, timeout and bounded scope. A supplied self-consistent digest is **not** proof of authorized origin: host verifies pinned reviewed source and caller continuity under the explicit same-UID/install trust premise.
- Anti-replay: consume the one-shot frame once, nonce scoped to this instance/run, prohibit frame reuse or post-READY replacement, reject unexpected extra FDs; parent death/EOF before handshake or child spawn => no Git.
- **Negative tests C1-N1…N7:** direct `python -I -m llmtool._git_add_host` with no inherited pipe; forged ordinary file/socket FD; replayed nonce; digest or parent/source mismatch; frame >16 KiB; early EOF/short read; delay/timeout or wrong domain. All must STOP **before first Git/supervisor child**. Test that no secret-bearing frame appears in `ps`, argv, env, logs or provider payload.
- If proof of trusted caller cannot be made robust within the supported single-user threat model, **STOP F1 and revise design**; merely knowing a nonce, PID or digest must not become arbitrary model/user execution authority.

## 4. Mandatory C2 — operator-wait terminal protocol and safe resolution

**Unknown containment is a live safety incident, not an ordinary timeout.** The dedicated `_git_add_host` retains the unreaped direct-supervisor anchor and ownership of liveness writer, status/control FDs, signal handlers, monitors and original error as required by the self-anchor amendment. It must **never** self-resolve or convert unknown containment to PASS because a wall-clock deadline, provider/model response, user-facing cancellation or process `kill(0)` passive observation expired.

**User/coordinator-facing bounded outcome** (no raw env, arbitrary paths or secrets):
`STATE_UNKNOWN / USER_ACTION_REQUIRED`, task/run digest, repository identity digest, last known owner/leader PID-PGID-SID + kernel start identity (labeled *last known, not permission to signal*), neutralized/sanitized relevant `.git/index.lock` existence/path reference (do not delete), trigger/primary fault, containment evidence refs, and a clear **STOP — do not retry, reset, remove lock or assume descendants gone**. Notify over a distinct bounded side channel; output failure must **not** release retained host responsibilities.

**Exactly one supported release/disposition action for this MVP:** `EXTERNALLY_VERIFIED_CONTAINMENT_RESOLVED` submitted by the **separate trusted incident-resolution authority**, not by the model or ordinary CLI. It requires fresh, independently obtained evidence that the *entire identified original child/descendant tree* is gone (including any observed escaped group), supervisor ownership/reap state is accounted for, no reuse-ambiguous identity remains, bound repository lock/index/HEAD/ref state is read-only classified, and an independently reviewed durable incident record exists. On acceptance, the Host may finalize its retained responsibility **only by the separately reviewed bounded terminal protocol**; it must not itself send group signals on remembered numeric IDs, delete locks, restore user data or retry Git. No unauthenticated `ACK`, elapsed timeout, manual PID input or model text is an acceptable release action.

If an escaped/unknown process cannot be proven gone, this single action is **unavailable**: retain operator-wait; external remediation must be separately designed/authorized with actual Mac/OS evidence before it can become a supported workflow. The owner is the product acceptor, **not** the technical process investigator by default; AI/authorized technical operator must own the incident response where access exists. The coordinator must not falsely promise remote Mac process handling if no Mac access exists.

**Required C2 tests:** unknown child ownership, supervisor unavailable, host cancellation, dropped status pipe/EPIPE, report failure, indefinite retained wait past normal run budget, false external ack, stale/reused PID, missing descendant or escaped group, lock file present, and valid trusted independently sourced resolution. Verify no ordinary success, no automatic process reap/handler restoration, no unsafe `killpg`, no blind retry and stable sanitized diagnostics. **Unresolved operator-wait remains a hard production blocker even if fixture tests pass;** do not ship a public hanging process without a demonstrably usable incident-response path.

## 5. Mandatory C3 — actual Git ADD, external helpers and escaped descendants

**Session model approved for design (but must be proved in product code):**

```text
new reviewed standalone sealed Host: single thread, default SIGCHLD
  -> direct owned supervisor: new session, PID=PGID=SID
     -> fixed Git ADD child + all descendants: inherit supervisor PGID/SID
```

Supervisor self last-act may signal **current group** only after its own live identity check; host may signal group only while holding freshly verified **unreaped direct supervisor** ownership/identity. Kill decision precedes reap. Never signal unrelated remembered PGID after ownership lost. A real Git descendant that calls `setsid`/`setpgid` or otherwise escapes the supervisor group means `containment_confirmed=false`, `STATE_UNKNOWN / USER_ACTION_REQUIRED`, **never `APPLIED`**. If descendant identity/completeness cannot be proved, fail closed; absence of a conveniently visible child is not proof that none escaped.

**Git ADD can execute external programs even without user-facing hooks.** Before allowing a fixture mutation, Codex must prove the entire reachable executable surface is neutralized or rejected: named `filter.*.clean`/`filter.*.process`, `.gitattributes` and `.git/info/attributes` drivers plus global/system attributes, `core.fsmonitor`, `core.hooksPath` and `post-index-change`, external Git command/helper paths, credential/ASKPASS/SSH/GPG, config `include/includeIf` and environment-injected Git config, `core.attributesFile`, `core.alternateRefsCommand`, protocols, optional maintenance, repository config/sparse/alternate worktree paths and any platform-specific executable attribute. Reuse **A5/A11b.2.1 fixed Git argv/config/env and read-only provenance**; do not trust only default hook configuration. If Git allows a filter/command through repo-controlled attributes despite static checks, STOP and use a separately reviewed OS sandbox or reject that repo layout. The ability to create an arbitrary `git add` command is **not** granted.

**Mandatory malicious fixture tests C3-N1…N10:** executable marker `filter.<driver>.clean`, long-lived `filter.<driver>.process`, `.gitattributes` filter declaration (including inherited/global patterns), `core.fsmonitor`, `core.hooksPath` + `post-index-change`, includeIf config, ambient `GIT_CONFIG_*` and credential helpers, symlink/escaped Git dir, descendant with different PGID/SID (using controlled synthetic process, never an uncontained real external helper), changed index.lock/HEAD/ref between preflight and spawn. For each, either reject *before* child spawn with stable typed outcome, or independently prove the exact approved safety configuration suppresses execution and no helper marker / escaped child appears. Never accept `APPLIED` if actual descendants escaped or proof is incomplete.

**Required positive/negative post-state:** bound tracked edit stages; bound new untracked file stages; unrelated staged/unstaged/untracked data remains untouched; `post-index-change` never runs; exit0 but unchanged semantic pre-state => `NOT_APPLIED`; exit nonzero/interrupted with exact expected semantics => `APPLIED_BUT_CONTROL_INTERRUPTED`; no-op first-match rule; lock/HEAD/ref/layout drift overrides expected index; unexpected index state => `USER_ACTION_REQUIRED`; uncontained/unknown process => `STATE_UNKNOWN` even when provisional index looks expected. Compare the full B5 §14.1 ordered path/mode/OID/stage/flag semantics, not raw index SHA alone. Never delete index.lock, `git reset --hard`, `clean`, auto-retry or rollback unfamiliar user content.
