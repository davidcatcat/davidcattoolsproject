## 3. Mandatory C1 — private inherited caller→Host channel

Use **one anonymous, inherited, unidirectional pipe** from the single reviewed **F1 fixture launcher** `llmtool._git_add_private.run_fixture_add(...)` (private, not exported by CLI/Agent/provider) to `llmtool._git_add_host`. Parent launches exactly `python -I -m llmtool._git_add_host`, `shell=False`, `close_fds=True`, with one designated read-only pipe FD passed via `pass_fds` (fixed target FD such as 3, using deliberate `dup2` in a synchronous single-thread fixture launcher **before** spawn; do not introduce unsafe `preexec_fn` in a multi-threaded process). Parent owns the write-only end. Host verifies `S_ISFIFO(os.fstat(fd).st_mode)`, `fcntl.F_GETFL & O_ACCMODE == O_RDONLY`, only expected inherited FDs, and the reviewed product-only module/manifest before spawning a supervisor. **This is continuity and misuse prevention, not authentication against malicious same-UID code.** Any additional Host→supervisor control/status/liveness pipes remain independently scoped as in B5; do not conflate these two channel layers.

- **No secrets or authority in argv, environment, filesystem path, URL or public CLI flags.** Use the fixed private launcher entry above, a reviewed product-only manifest excluding `tests/`, and isolated `-I` module invocation. **No `--fd`, public CLI/router, model-supplied caller identity, extra credential, privileged helper, second transport or secret authorization token.** A direct `-m` invocation without the fixed inherited FIFO is rejected. Under the F1 **same-UID, trusted-installation premise** any same-UID code can execute Git independently; no claim that the launcher, nonce, hashes, marker or FIFO cryptographically authenticates a malicious same-UID caller.
- Frame format **fixed and bounded (Claude's PR #76 R1 applied)**: 4-byte unsigned big-endian byte length followed by **one** canonical UTF-8 JSON object. Total envelope cap **128 KiB (131,072 bytes)**, existing typed canonical `Action` cap **64 KiB (65,536 bytes)** from `action_contract.JSON_LIMIT`, and independent **non-Action handshake/binding metadata cap 16 KiB (16,384 bytes)**. **Serialize the outer envelope with the identical canonical JSON settings used by `action_contract._canonical`: `json.dumps(..., ensure_ascii=False, separators=(',', ':'), sort_keys=True, allow_nan=False).encode('utf-8')`.** Embed Action as a **nested JSON object**, never a JSON-escaped string, opaque binary or duplicate Action copy. Compute the Action sublimit **only** by canonically reserializing that nested Action object using those settings, then calling `parse_action()` on its decoded UTF-8 bytes to validate the complete typed value; do not use a second serializer, Python character-count shortcut, or trust self-reported lengths/digests. Canonically reserialize the metadata-only object (excluding Action) with the same settings for its independent 16 KiB bound. The 128 KiB outer cap is measured in actual raw UTF-8 bytes, with one length-prefixed frame, strict schema/duplicate-key/depth/boundary limits, <=2s handshake deadline, exact trailing-data/EOF validation and no extra transport/authority. Reject overlimits before supervisor/Git spawn with sanitized `AUTHORITY_REJECTED`/`NOT_SUPPORTED`. Sender/receiver need bounded streaming/deadline and EPIPE handling (full Action exceeds typical OS pipe buffering); no unbounded memory, deadlock or silent `ensure_ascii=True` fallback. Existing non-ASCII paths and `MAX_FILES=32` remain supported *within the existing Action path grammar*.
- Bind protocol/version/domain `A11b.2.2.2/git-add/internal/v1`, fresh per-run nonce, *observed* parent kernel PPID/UID/start identity, validated product module origin/hash/manifest (no `tests/` paths), interpreter/install origin, canonical Action digest, `GitAddPreflight` digest, fixture root dev/inode, HEAD/ref/OID, baseline index and expected semantic state, authorized paths, timeout and scope. The host verifies parent identity **against independent kernel observations** and requires fresh single-use frame before spawn; the supervisor independently reruns B5 §5 preflight before Git. **PPID, UID, nonce, hash and a well-formed frame prove continuity/consistency only, not authorized origin.** The F1 security boundary for where Git may write is the independently checked **disposable fixture provenance** in §3A.
- Anti-replay/misdirection within the trusted F1 flow: consume the one-shot frame once; bind nonce to fresh per-run fixture marker and parent continuity; prohibit frame reuse, old nonce with new fixture, post-READY replacement and extra unexpected FDs. Parent death/EOF before handshake or spawn => no Git. Do **not** represent a model-supplied nonce or sender-provided digest as an unforgeable same-UID identity proof.
- **Negative C1-N1…N7 and encoding/size-bound positives:** direct `python -I -m llmtool._git_add_host` without inherited pipe; forged ordinary file/socket FD; replayed nonce; digest/parent/source mismatch; frame >**128 KiB**, nested canonical Action >**64 KiB**, metadata-only binding >**16 KiB**, wrong declared length, extra bytes, duplicate keys, invalid UTF-8, early EOF/short read, deadline/EPIPE/stalled pipe and wrong domain. All reject **before Git/supervisor spawn**. Positives: the actual 32-path **57,430-byte** ASCII Action; near-maximal valid **3-byte CJK (`測`) paths**; near-maximal valid **4-byte Unicode CJK Extension B (`𠀀`) paths**; and a valid near-64-KiB Action with bounded metadata. All must round-trip through canonical `ensure_ascii=False` outer-envelope parsing, `Action.to_json()` / `parse_action()`, verified digests and source/nonce binding, without ASCII escaping/Action double encoding, and without deadlock beyond pipe buffer. **Current `_path` allows alphanumeric Unicode but rejects ordinary emoji (`😀`.isalnum() is false); add an explicit emoji-path rejection test instead of altering Action's permitted path grammar.** Also verify an outer `ensure_ascii=True` regression would inflate near-boundary Unicode and is never selected. Check no secret-bearing frame appears in argv, environment, process listings, logs or provider outputs.
- **F1 accepted boundary:** enforce concrete *invocation-shape, trusted-code-integrity, parent-continuity and disposable-fixture provenance* checks, not the impossible requirement to distinguish a malicious same-UID self-consistent caller. If a condition in §3A cannot be independently checked without new authority, **STOP before supervisor/Git spawn**; do not invent an issuer, credential, service or new communication channel. This exception is **F1-only**; later production runtime must undergo its own A11b.3 authorization/security review.

## 3A. Claude [Issue #70 Security ruling](https://github.com/davidcatcat/davidcattoolsproject/issues/70#issuecomment-6084907203): F1 fixture provenance and bounded admission

**Controlling premise:** F1 runs with the same UID as a trusted reviewed private launcher; it prevents accidental/misdirected Git writes, **not** deliberate tampering by hostile same-UID code. The source/manifest, frame, nonce and parent checks are independent *consistency and continuity* controls. **The Host and Supervisor must fail closed on any uncertain fixture identity before spawning Git.**

**A — numbered Host admission MUST and how to satisfy it** (also the pre-Codex feasibility matrix):
1. **Reviewed executable identity** — launch fixed `sys.executable -I -m llmtool._git_add_host` from isolated installed product path; Host checks `__main__.__file__`/module origin against the reviewed code manifest and exact interpreter identity. Product manifest excludes `tests/containment_probe_parent.py` and all fixture-only artifacts. **Feasible:** source locations and SHA-256 can be computed from current installed bytes and compared before spawn; reject missing/changed/ambiguous runtime/manifest.
2. **Fixed private FIFO read descriptor** — create `os.pipe()`, launcher assigns fixed read FD (e.g. 3) while single-threaded, `Popen(close_fds=True,pass_fds=(fd,),shell=False)`, never `--fd`. Host checks `os.fstat` pipe type, `fcntl.F_GETFL` read-only access mode, and the bounded list of extra FDs; reject missing/regular file/socket/unexpected inherited descriptor. **Feasible:** normal stdlib OS APIs; test Darwin/python 3.9/3.14 behavior, single-thread/FD collisions, `dup2` ownership/restoration and unsupported FD enumeration. A generic model/CLI must not call the private adapter. Never use a multi-threaded `preexec_fn` escape.
3. **Observed parent continuity** — compare `os.getppid()`, kernel UID and stable parent PID start identity to expected frame fields using existing `_git_process_identity.py` facilities. **Feasible:** identity utilities already exist but remain subject to native Mac verification; mismatches, PID reuse, unavailable start identity and parent death fail closed. No interpretation as same-UID malicious caller authentication.
4. **Canonical bounded one-shot frame** — fixed domain, 128 KiB overall / 64 KiB canonical Action / 16 KiB bound metadata, UTF-8 `ensure_ascii=False`; fresh nonce, one read, <=2s read deadline, reject wrong domain, replay, EOF, extra/trailing frame data. **Feasible:** use fixed prefix and bounded streaming; verify legal 32-path + CJK 3-byte and 4-byte supplementary-character cases, invalid emoji paths and malicious frames. Avoid deadlock for payload larger than pipe buffer.
5. **Supervisor's independent binding and drift check** — Host validates Action/preflight digests, exact source+scope and fixture identity; *supervisor itself* reruns `preflight_git_add(action)` and must compare exact Action/repo/HEAD/ref/index/source/authorized paths/expected post-state **immediately before Git spawn** (B5 §5). **Feasible:** existing `git_mutation.preflight_git_add` returns typed read-only evidence; adapter is new private code. Fail-closed on TOCTOU/unavailable verification, no authority from a self-consistent frame.

**B — numbered disposable-fixture MUST and how to satisfy it** (the F1 mutation-target boundary):
1. **Fresh OS temporary root:** private launcher creates `tempfile.mkdtemp(prefix='llmtool-f1-')` **under `os.path.realpath(tempfile.gettempdir())`** before creating a Git repo; pin that exact absolute realpath and root dev/inode in the handshake. Host checks the requested Git worktree's canonical realpath is **strictly within** that newly created root, not the project root, and that all ancestry components inside the fixture are symlink-free. **Feasible:** `realpath`/component `lstat`/fd-anchored `openat` or equivalent; `/tmp`→`/private/var` aliases are normalized, not incorrectly rejected. The directory prefix **alone is never trusted**.
2. **No user-repo alias or overlap:** independently check canonical project-root dev/inode is different from fixture repo; reject the canonical project path, any fixture/root alias, descendant pointing into home outside the temporary fixture, a root that is an ancestor of the user home/project root, symlinked worktree or Git directory, or any `git rev-parse --show-toplevel` not exactly equal to the validated fixture Git worktree. **Feasible:** read-only Git top-level query plus root identity/path ancestry; refuse any path resolution, symlink or reparse ambiguity. Do not mutate or use the canonical worktree as a fixture.
3. **Creation-order marker:** launcher creates `.llmtool-f1-fixture` at the temporary-root level **before** `git init`, with `os.open(O_CREAT|O_EXCL|O_WRONLY|O_NOFOLLOW, 0o600)`, writes this run's nonce, then closes it. Host checks `lstat`: regular file, owner == UID, exact 0600 mode, no symlink, nonce equals frame, and marker is creation-ordered **before** the fixture `.git`. **Feasible:** launcher explicitly writes marker first, then creates `.git`; confirm via supported birth/ctime metadata or recorded creation ordering that cannot be confused by later chmod/write; if time granularity/order cannot be established, STOP rather than assert a timestamp proof. Never accept a forged marker claim as same-UID authentication.
4. **Independence at last possible instant:** Host validates root/marker and passes pinned dev/inode/nonce details to supervisor; **supervisor repeats the fixture/root/marker checks and Action preflight immediately before Git spawn**, comparing identities with parent. **Feasible:** tested read-only lstat/openat/root checks; any drift, changed symlink, removed/replaced marker, changed HEAD/ref/index or unverified parent => no Git spawn.

**Required negative/positive tests before F1 PASS:** direct `python -I -m` lacking inherited pipe, ordinary file/socket at FD3, replayed old nonce, wrong PPID/start time, missing/extra inherited FD, source mismatch, wrong marker mode/owner/nonce, absent marker, marker not predating `.git`, directory with only `llmtool-f1-` prefix but no evidence, symlinked fixture/root/`.git`, fixture outside OS temp root, canonical actual project repository as target, `git rev-parse` root mismatch, altered root dev/inode between Host and supervisor. Include positive real isolated temporary fixture, valid Git ADD on authorized data only and unchanged unrelated files. Never create a helper service, privileged credential, second channel, model-facing launch path or public user-repo mutation capability to satisfy these tests.

**F1 limitation and evidence:** these checks cannot stop an actively malicious same-UID caller with filesystem/process control; document this exact trust assumption in the final PR. The **test harness owns test fixture termination/cleanup only**; it cannot declare lost descendants safe. Mac/native/CI/source QA remain **PENDING until run on frozen implementation bytes**, and this documentation approval is not authority to mutate the canonical repo.

## 4. Mandatory C2 — F1 operator-wait with NO in-band release

**Unknown containment is a safety incident, not an ordinary timeout.** The dedicated `_git_add_host` retains the unreaped direct-supervisor anchor, unique liveness writer, all control/status FDs, signal handlers, monitors, original error and ownership evidence. If child/group identity or disappearance cannot be established, emit a bounded, sanitized `STATE_UNKNOWN / USER_ACTION_REQUIRED` incident notification and **remain in operator-wait indefinitely**. The host must not ordinarily return, reap the supervisor, restore handlers, close critical FDs, kill remembered numeric process identities, retry Git, remove locks or change outcome to PASS/APPLIED after any timer, cancellation, provider/model response or report failure.

**Bounded incident notice** records task/run and repository identity digests, last known PID/PGID/SID and kernel start identity **labeled observations, not signaling authority**, sanitized `.git/index.lock` state, known containment evidence and a precise **STOP: do not retry/reset/delete lock or assume descendants are gone**. A lost/broken notification channel must not relax retained responsibility. This is the F1 fixture host only, not a public CLI incident feature.

**No `EXTERNALLY_VERIFIED_CONTAINMENT_RESOLVED` action is implemented in F1.** No in-band ACK, authenticator, model approval, trusted resolver credential, callback, resume API, timer-driven release or imagined incident-resolution authority. **The sole supported F1 way out** is an external technical operator manually terminating the retained host **after examining evidence**. Termination is **not proof of group containment** and not authorization to kill uncertain descendants, delete locks, retry or call Git staging successful. The **recorded outcome stays `STATE_UNKNOWN / USER_ACTION_REQUIRED` permanently**, including after externally terminating the host. Actual surviving descendants require separately authorized external investigation; the user is not made the default technical incident resolver.

**C2 fixture regression:** drive unknown identity, lost supervisor, cancel, EPIPE/dropped status, reporting failure, stale/reused PID, escaped group and index.lock. Verify the retained host stays blocked for **≥ run budget + an explicit safety margin**, with no normal return, host-driven reap, signal-handler restoration, unsafe killpg or retry. The **test harness then externally terminates that disposable fixture host**; the recorded result remains `STATE_UNKNOWN` with **no host-driven reap or handler restoration**. The test owns its disposable fixture/descendant cleanup under a separately bounded test-only procedure; killing the host does not count as descendant disappearance or recovered state.

**F2 only (deferred):** design `EXTERNALLY_VERIFIED_CONTAINMENT_RESOLVED`, any trusted incident authority/credential, authenticated terminal release channel and independently proven safe resolution for product runtime. Codex is explicitly **forbidden to invent or implement these in F1**. Without F2's reviewed operator-resolution process, even a passing F1 fixture is **not production-ready**.

## 5. Mandatory C3 — actual Git ADD, external helpers and escaped descendants

**Session model approved for design (but must be proved in product code):**

```text
new reviewed standalone sealed Host: single thread, default SIGCHLD
  -> direct owned supervisor: start_new_session=True, PID=PGID=SID
     -> fixed Git ADD child + all descendants: start_new_session=False,
                                               inherit supervisor PGID/SID
```

Supervisor self last-act may signal **current group** only after its own live identity check; host may signal group only while holding freshly verified **unreaped direct supervisor** ownership/identity. Kill decision precedes reap. Never signal unrelated remembered PGID after ownership lost. A real Git descendant that calls `setsid`/`setpgid` or otherwise escapes the supervisor group means `containment_confirmed=false`, `STATE_UNKNOWN / USER_ACTION_REQUIRED`, **never `APPLIED`**. If descendant identity/completeness cannot be proved, fail closed; absence of a conveniently visible child is not proof that none escaped.

**Git ADD can execute external programs even without user-facing hooks.** Before allowing a fixture mutation, Codex must prove the entire reachable executable surface is neutralized or rejected: named `filter.*.clean`/`filter.*.process`, `.gitattributes` and `.git/info/attributes` drivers plus global/system attributes, `core.fsmonitor`, `core.hooksPath` and `post-index-change`, external Git command/helper paths, credential/ASKPASS/SSH/GPG, config `include/includeIf` and environment-injected Git config, `core.attributesFile`, `core.alternateRefsCommand`, protocols, optional maintenance, repository config/sparse/alternate worktree paths and any platform-specific executable attribute. Reuse **A5/A11b.2.1 fixed Git argv/config/env and read-only provenance**; do not trust only default hook configuration. If Git allows a filter/command through repo-controlled attributes despite static checks, STOP and use a separately reviewed OS sandbox or reject that repo layout. The ability to create an arbitrary `git add` command is **not** granted.

**Mandatory malicious fixture tests C3-N1…N10:** executable marker `filter.<driver>.clean`, long-lived `filter.<driver>.process`, `.gitattributes` filter declaration (including inherited/global patterns), `core.fsmonitor`, `core.hooksPath` + `post-index-change`, includeIf config, ambient `GIT_CONFIG_*` and credential helpers, symlink/escaped Git dir, descendant with different PGID/SID (using controlled synthetic process, never an uncontained real external helper), changed index.lock/HEAD/ref between preflight and spawn. For each, either reject *before* child spawn with stable typed outcome, or independently prove the exact approved safety configuration suppresses execution and no helper marker / escaped child appears. Never accept `APPLIED` if actual descendants escaped or proof is incomplete.

**Required positive/negative post-state:** bound tracked edit stages; bound new untracked file stages; unrelated staged/unstaged/untracked data remains untouched; `post-index-change` never runs; exit0 but unchanged semantic pre-state => `NOT_APPLIED`; exit nonzero/interrupted with exact expected semantics => `APPLIED_BUT_CONTROL_INTERRUPTED`; no-op first-match rule; lock/HEAD/ref/layout drift overrides expected index; unexpected index state => `USER_ACTION_REQUIRED`; uncontained/unknown process => `STATE_UNKNOWN` even when provisional index looks expected. Compare the full B5 §14.1 ordered path/mode/OID/stage/flag semantics, not raw index SHA alone. Never delete index.lock, `git reset --hard`, `clean`, auto-retry or rollback unfamiliar user content.
