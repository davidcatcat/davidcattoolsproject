## Suspected native correctness defect — not proven runtime cause

Claude already noted that `identity()` calls `os.getsid(pid)` while the owned
supervisor may be a zombie after CANCEL/self-group SIGKILL. Parent cleanup then
calls `Anchor.kill_group`, which repeats that identity lookup before its group
decision. If the SID query fails for the zombie, containment becomes unresolved.

Apple XNU's `getsid` implementation uses `proc_find` and returns ESRCH when it
cannot find the process. XNU has separate zombie lookup paths. This supports the
hypothesis, but upstream source is not proof of the failure on David's exact OS:

- https://github.com/apple/darwin-xnu/blob/main/bsd/kern/kern_prot.c
- https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_proc.c

Other cleanup/notification/group-disappearance paths remain possible. Do not label
the root cause confirmed or replace identity verification with guessed SID/PGID.
