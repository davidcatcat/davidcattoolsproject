# D6 task worktree lifecycle (normative)

Owner D6 permits additional registered, task-scoped linked worktrees without the former two-root limit or per-task Owner approval ([D6 decision](../../docs/decisions/llmtool_dynamic_worktree_20261019.md)). This reference owns the current local registry, creation, handoff, retention and retirement gates. The canonical Integrator/native-acceptance checkout remains protected and is never disposable. D6 does not grant F2, provider egress, secret access, force operations, automatic merge or unrestricted filesystem authority. Native F1 acceptance runs only in the canonical checkout.

## Roots and registration

On the authorized Mac, new task worktrees use unique children under:

`/Users/davidsun/.local/share/llmtool-dev-workspaces/davidcattoolsproject/tasks/`

The parent is `/Users/davidsun/.local/share/llmtool-dev-workspaces/davidcattoolsproject/`. Do not use the canonical checkout, an arbitrary clone, a temporary directory or another Agent's root. Existing `codex` and `claude` roots require verified owner/session release and transfer; never silently reuse them.

Resolve the real Git common-dir from the canonical checkout. Store each host-owned local record at `<absolute-real-git-common-dir>/llmtool-worktrees/<task-id>.json`. The registry directory is owner-only mode `0700`; each record is owner-only mode `0600`, created or updated atomically under serialized Integrator coordination. Validate repository/common-dir/root identity, safe task-id characters, and absence of symlink traversal or path escape.

Each `schema_version=1` record contains `task_id`, trusted `agent_id`, `session_ref`, `lease_ref` (verify liveness independently), `root_realpath` and physical identity, `git_common_dir`, `branch`, `base_sha`, `head_sha`, optional `pr_number`, `state`, `last_verified_at`, `evidence_refs`, exact-path `retention_paths`, `lock_state`, and `disposition`. Missing, malformed, conflicting or identity-mismatched records are not authority to adopt or remove a directory: set `RETAIN_BLOCKED` and preserve it. The registry is an inventory, not a PID lock or model-authored permission. Keep local paths, session tokens and private inventories out of GitHub.

## Create and hand off

1. Bind the task/Issue/PR, actual Agent and live Session/lease, unique branch, approved base SHA and canonical common-dir. The Integrator/PM selects the Worker and supplies those already-authorized bindings; this helper records them but does not grant task, provider or filesystem authority.
2. Create and prepare the task tree only through `python3 -B -I tools/llmtool/scripts/d6_worktree_lifecycle.py --task-id <task-id> --agent-id <trusted-agent-id> --session-ref <live-session-ref> --lease-ref <live-lease-ref> --branch <unique-branch> --base-sha <approved-base-sha>`. The entrypoint checks the repository identity, base and safe Git branch name; creates the linked worktree under the fixed D6 tasks directory; applies owner-only root mode; atomically writes the owner-only registration with ENV-2 retention paths, including `tools/llmtool/.d6-bootstrap-report.json`; locks the Git worktree; then invokes ENV-2 and returns `D6_WORKTREE_READY` only after bootstrap passes. ENV-2 writes a private structured report bound to task ID, HEAD and cache fingerprint. The report records observed cache state, elapsed steps, download/install counts and package versions; raw stdout/stderr are discarded. The shared read-only wheel cache remains outside the worktree. Do not substitute direct `git worktree add` plus a later Developer start; a failed create, registration, lock or bootstrap stops the Worker start and preserves any created tree for repair.
3. ENV-2 validates the registered identity, `ACTIVE` or resumable `REPAIR` state, root mode and inode, exact registered HEAD/base, locked live Git worktree, bootstrap-source binding and untracked/ignored inventory before invoking `make -f Makefile env-bootstrap`. The managed llmtool OpenCode dispatch path repeats this ENV-2 validation/bootstrap immediately before starting the Developer and revalidates the D6 binding at process launch. For a direct native Codex/Claude CLI session, the Integrator must complete the lifecycle entrypoint successfully before starting or resuming that session; the repository does not claim a native CLI startup hook unless one is independently verified. After preparation, confirm root, common-dir, branch, HEAD and tracked/untracked/ignored inventory before source edits, including that generated files stay within `retention_paths`. Keep one writer per tree and isolate venv/build/import state.
3. Record task state as `ACTIVE`, `REVIEW_PENDING`, `REPAIR`, `RETIRE_READY`, `RETAIN_BLOCKED` or `REMOVED`. Bind source, owner, root, branch, HEAD, allowed files and evidence at task start and completion.

The canonical checkout has one Integrator writer under the Owner-approved canonical Integrator/native-acceptance workflow. Before any canonical source/Git write, independently verify the root, branch, HEAD, remote, tracked/untracked state and that no other writer or child process is using it; post `CHECKOUT-CLAIM <agent> <task-branch> <observed-HEAD>` in the task handoff. A PR publication or review request is not release. After publishing and stopping owned tests/descendants, return to `main` only if clean, reverify state, and post `CHECKOUT-RELEASE <agent> main <HEAD>`. If unsafe, post HOLD without switching or cleaning. These comments are not locks; each next Integrator independently verifies exclusive ownership and fresh state. Git worktrees share refs and remote-tracking state, so serialize conflicting checkout, fetch, push, merge and ref updates across tasks. Before a canonical-root handoff, verify the prior writer/session and descendants have released it. A Developer does not write in the canonical root; a PID alone is not proof of release.

## Retain or retire

A PR open, self-review PASS, elapsed time or Agent saying `done` does not authorize retirement. Retire only after the PR is merged **and** the task is accepted/closed, or after cancellation/rejection with a recorded keep/discard disposition. Keep active or repair trees. Keep review-pending trees unless all processes are released, exact candidate/evidence are preserved outside the tree, and the task can be safely recreated from published refs at the same reviewed SHA without losing state.

Before removal, verify the exact registered noncanonical path, owner/session/lease release, no running tests/children/reviewers, expected common-dir/branch/HEAD/lock, no Git locks, and no later unpublished work. Inspect staged, unstaged, untracked and ignored contents. Git removal can silently delete ignored files, including venvs or evidence; classify every exact retention path as `KEEP/EXPORT` with verified preservation or `DISCARD_REGENERABLE` after confirming it contains no unique data, secrets, recovery state or evidence. Delete only exact `DISCARD_REGENERABLE` paths listed in the registry, after confirming each path resolves beneath the task root; never follow symlinks, use globs or recursively delete a directory. Remove only exact files with ordinary path-scoped deletion; use ordinary `rmdir` only for an explicitly listed empty directory. If safe exact removal is unclear, leave it and mark `RETAIN_BLOCKED`. Unknown or ambiguous content means `RETAIN_BLOCKED`. Never kill a process to make cleanup pass.

For a squash merge, authoritative PR metadata must show merged/accepted and its final published PR head SHA must equal the local task HEAD. Preserve independent review, CI, source and retention evidence outside the tree. Only the Integrator may later delete that exact local task branch with `git branch -D`, and only for an accepted squash-merged PR with matching final head SHA and no other task/worktree/PR dependency. Do not delete remote refs or unrelated branches/tags. Cancellation of unmerged work requires its explicit recorded disposition.

When every gate passes, unlock only the exact D6-owned locked tree, recheck identity and liveness, then run ordinary `git worktree remove <exact-path>` without `--force`. Verify it is absent and record `REMOVED`, final SHA, task/PR, disposition, evidence and time. Failed unlock/removal means `RETAIN_BLOCKED`; never force-retry.

## Hard Git safety limits

Do not use `git reset --hard`, `git clean`/`clean -fd`, forced checkout/switch, `git switch -B`, force push, history rewrite, `git worktree prune`, `git gc`/`prune`, shared Git config mutation, unregistered `git worktree move`/`repair`, or `rm -rf` to bypass preservation. Do not stash unrelated work or delete branches/tags outside the exact D6 squash rule above. Developers must not check out `main`; do not fetch unclaimed refs in the canonical Integrator checkout.

This policy is not Mac runtime evidence. Until the actual path demonstrates create, parallel work, accepted-task removal and interrupted/dirty preservation, report D6 auto-retirement as **NOT LIVE VERIFIED**.
